# Brain Route and Dual-Layer Authority

canonical_rule_id: JF_DL_BRAIN_FIRST_RULE
source_section_id: 01::BRAIN_FIRST

User intent goes to the single Web Brain first. Codex receives only one complete Brain-bounded Prompt under the route-appropriate authorization: under the current active Development Project Instruction, bounded pure read-only discovery may be authorized by the Web Brain without a separate user approval, while every mutation/material execution still requires explicit user approval of the exact current mutation envelope. Joyflow remains one Web Brain, one local Codex Executor and user-mediated semi-automatic control.

canonical_rule_id: JF_DL_REPOSITORY_CANONICAL_TRUTH_RULE
source_section_id: 01::REPOSITORY_CANONICAL_TRUTH

The repository default branch, merged code, merged tests and active repository-visible schema/configuration are persistent project facts. An open branch or PR is candidate state. Task Capsules, Prompts, approval views, repair packets and intermediate evidence are temporary unless an independently justified repository-visible artifact is merged.

canonical_rule_id: JF_DL_DUAL_LAYER_CLOSURE_RULE
source_section_id: 01::DUAL_LAYER_CLOSURE

Joyflow uses a Repository-Anchored Dual-Layer Closure Model: repository canonical state is the durable project layer; a bounded Fibered Task Capsule is the temporary current-task layer. Projection creates a Codex Prompt. Brain review, user acceptance and user merge approval remain human gates before a repository result can become durable fact.

canonical_rule_id: JF_DL_PROJECTION_PROMOTION_SEPARATION_RULE
source_section_id: 01::PROJECTION_PROMOTION_SEPARATION

Projection authorizes bounded execution only. It never authorizes merge. Codex may create or update a candidate PR and return evidence, but cannot fill Brain review, user acceptance, merge approval or repository-result status. The Web Brain reviews current raw materials; the user separately authorizes execution and final merge.


canonical_rule_id: JF_DL_BRAIN_GITHUB_DISCOVERY_AUTHORITY_RULE
source_section_id: 01::BRAIN_GITHUB_DISCOVERY_AUTHORITY

The Web Brain uses GitHub repository, PR, commit, diff and file evidence as the default first discovery surface for ordinary work. Ordinary structurally-clear work may stay on the Brain-bounded fast path. When material architecture uncertainty cannot be safely closed from current Web-visible evidence, the Brain frames the exact structural question instead of prescribing the repository architecture; under the user-confirmed architecture direction and after the replacement Project Instruction is confirmed, the Brain may authorize that exact bounded pure read-only Codex structural discovery without creating a separate user approval state, before final mutation paths are frozen. Codex produces repository-grounded structural facts, semantic relations, candidate technical routes and a recommendation. The Web Brain reviews that proposal from the whole-project product/architecture perspective and owns final technical closure and final allowed-path selection within user-approved product scope.


canonical_rule_id: RULE_CODEX_BOUNDED_TECHNICAL_AUTHORITY
source_section_id: 01::CODEX_BOUNDED_TECHNICAL_AUTHORITY

Codex is the bounded execution technical authority for the current local repository and runtime. It independently preflights the Brain route, selects equivalent implementation details inside the approved product semantics and paths, and must stop with a source-bound technical objection when direct evidence conflicts with the route or the approved scope is insufficient. Codex never becomes a second semantic Brain and cannot change product requirements, authority topology, allowed paths, Brain review, user states, or merge authority.

canonical_rule_id: RULE_BRAIN_TASK_BOUND_PREFLIGHT_SUBJECTS
source_section_id: 01::BRAIN_TASK_BOUND_PREFLIGHT_SUBJECTS

The Web Brain fixes the preflight dimensions and current-task subjects that cannot be skipped, not the implementation answer Codex must produce. Each obligation uses the canonical question for its dimension and binds the exact current execution object, Brain route assumptions, approved path decision, validation duties, material semantics, non-goals, test plan or migration/compatibility boundary. Non-empty but unrelated questions do not satisfy the obligation.

canonical_rule_id: RULE_STRUCTURAL_QUESTION_BRAIN_AUTHORITY
source_section_id: 01::STRUCTURAL_QUESTION_BRAIN_AUTHORITY

For a structurally escalated task, the Web Brain owns the decision frame that says whether structural discovery is required, which current architecture question must be answered, which dimensions are material, which product semantics/non-goals must be preserved and what bounded discovery seed is justified. The Brain frame does not prescribe the technical answer, class pattern, state owner or final mutation path. Codex must answer the exact Brain-owned question against current repository evidence and cannot silently rewrite, narrow, downgrade or mark the required frame not applicable.

canonical_rule_id: RULE_BRAIN_WHOLE_PROJECT_STRUCTURAL_REVIEW
source_section_id: 01::BRAIN_WHOLE_PROJECT_STRUCTURAL_REVIEW

The Web Brain is the whole-project structural reviewer and final technical-closure authority, not the first detailed repository architect for a structurally uncertain task. It reviews Codex repository-grounded architecture proposals against the current product goal, protected semantics, non-goals, important tradeoffs, relevant long-term structural skeleton and cross-PR continuity. It may ACCEPT one exact Codex route, request targeted REWORK for a specific unresolved structural subject, or return a material product/protocol tradeoff to the user; it may not silently replace the Codex route with an ungrounded alternative while claiming continuity.
