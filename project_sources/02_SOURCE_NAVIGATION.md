# Source Navigation

canonical_rule_id: JF_DL_MINIMUM_SOURCE_LOADING_RULE
source_section_id: 02::MINIMUM_SOURCE_LOADING

Load the smallest sufficient source sections. Do not load all Project Sources merely because they are available. Expand only when a referenced invariant, route profile, domain lane or failure Gate requires it.

canonical_rule_id: JF_DL_SOURCE_TRUTH_BOUNDARY_RULE
source_section_id: 02::SOURCE_TRUTH_BOUNDARY

Joyflow Project Sources govern process. Repository-visible code, tests, schema and confirmed project artifacts govern project facts. Chat memory and temporary task capsules cannot override either source.

canonical_rule_id: JF_DL_GENERATED_ASSET_BOUNDARY_RULE
source_section_id: 02::GENERATED_ASSET_BOUNDARY

The dual-layer mechanical model is the control source for generated schemas and the generated registry. Generated assets must match byte-for-byte and never become an independently edited authority.

canonical_rule_id: RULE_STRUCTURAL_SKELETON_NAVIGATION_ONLY
source_section_id: 02::STRUCTURAL_SKELETON_NAVIGATION_ONLY

A sparse long-term structural projection may seed navigation to relevant lifecycles, authority boundaries and shared surfaces, but it is derived and commit-anchored. Current repository/source replay remains authoritative for the current task; stale or conflicting skeleton claims trigger current-source re-unfolding rather than overriding repository facts.
