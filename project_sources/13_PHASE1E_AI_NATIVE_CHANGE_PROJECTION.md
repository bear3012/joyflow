# Phase 1E — AI-Native Change Projection

canonical_rule_id: JF_PHASE1E_EXACT_PARENT
source_section_id: 13::EXACT_PARENT

PR1E extends only the exact passed PR1D frozen package recorded in `PHASE1_STAGE_LINEAGE.json`. Earlier PR1E or PR1F uploads are target material and cannot substitute for that implementation parent.

canonical_rule_id: JF_PHASE1E_CURRENT_SOURCE_PROJECTION
source_section_id: 13::CURRENT_SOURCE_PROJECTION

A Merged Change Projection is a conditional post-merge derived navigation artifact. When long-term continuity value justifies generating it, it binds the exact observed Task Completion Pointer, merged repository result identity, reviewed PR identity, approved Projection, Codex Return, Evidence Bundle, Codex execution block, Brain Review Capsule and complete reviewed Diff path set. It is regenerated from current exact sources rather than treated as a pre-merge authority.

canonical_rule_id: JF_PHASE1E_NAVIGATION_ONLY
source_section_id: 13::NAVIGATION_ONLY

The Merged Change Projection supports semantic retrieval and context recovery only. Current repository bytes, exact Diff, current tests and sealed Evidence remain the direct authority and cannot be replaced by projection content. Because it is navigation-only, absence of this artifact does not block PR CI, Merge Candidate Freeze, User Acceptance, User Final Merge Authorization or merge.

canonical_rule_id: JF_PHASE1E_PR_CI_EXACT_CONSUMPTION
source_section_id: 13::PR_CI_EXACT_CONSUMPTION

The public PR CI replays the exact current PR/review execution chain and current repository Diff without consuming a Merged Change Projection. A navigation-only projection cannot become a mandatory pre-merge Gate or substitute for current source replay.

canonical_rule_id: JF_PHASE1E_FREEZE_EXACT_PROJECTION
source_section_id: 13::FREEZE_EXACT_PROJECTION

The Merge Candidate Freeze consumes the exact current PR body, PR record, CI result, Projection, Return, Evidence Bundle and Brain Review Capsule after Brain Review PASS + CI PASS. It is created before applicable User Acceptance and before User Final Merge Authorization; it does not consume `MERGE_READY`, `MERGE_ALLOWED` or a Merged Change Projection.

canonical_rule_id: JF_PHASE1E_USER_MERGE_AUTHORIZATION
source_section_id: 13::USER_MERGE_AUTHORIZATION

User Final Merge Authorization is a separate USER-owned decision bound to the exact Merge Candidate Freeze and the independently recorded post-freeze User Acceptance disposition when applicable. Execution approval, Brain review, User Acceptance and merge authorization remain distinct decisions; the same explicit user message may express Acceptance and Final Merge Authorization, but their machine bindings remain separate. `MERGE_READY` and `MERGE_ALLOWED` are derived Gate results only.

canonical_rule_id: JF_PHASE1E_COMPLETION_EXACT_CHAIN
source_section_id: 13::COMPLETION_EXACT_CHAIN

A Task Completion Pointer records only an already observed repository merge and binds the exact Merge Candidate Freeze, post-freeze User Acceptance Capsule and USER Final Merge Authorization. It does not require standalone `MERGE_READY` / `MERGE_ALLOWED` lifecycle records and does not perform merge or Promotion.

canonical_rule_id: JF_PHASE1E_UNIFIED_GENERATION
source_section_id: 13::UNIFIED_GENERATION

All Model-derived Schemas, registries, base Capsule examples, PR records, CI results, freezes, user-decision bindings, optional post-merge projections and completion examples are regenerated from the same current Model and generator chain. Mixed-version or byte-drifted generated artifacts block package validation.
