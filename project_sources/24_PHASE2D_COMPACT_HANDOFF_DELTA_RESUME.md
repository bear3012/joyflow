# Phase 2D — Compact Complete Handoff and Delta Resume

canonical_rule_id: RULE_PHASE2D_COMPACT_COMPLETE_HANDOFF
source_section_id: 24::COMPACT_COMPLETE_HANDOFF

The existing CODEX_HANDOFF_PROJECTION remains the single execution projection. The one user-carried Prompt contains a deterministic model-visible compact current-task view plus a compressed exact machine envelope binding the complete Projection and Brain-recorded user execution approval. Compactness may remove duplicated transport representation but may not remove material product semantics, current-source context, execution boundary, validation obligations, return contract or stop conditions.

canonical_rule_id: RULE_PHASE2D_STATIC_RUNTIME_DYNAMIC_TASK_SEPARATION
source_section_id: 24::STATIC_RUNTIME_DYNAMIC_TASK

Stable schemas, mechanical validation rules, evidence-capture methods and repository utilities belong to the installed Joyflow Runtime. The dynamic Prompt carries the current goal, current-source context, approved execution boundary, validation and stop conditions. This separation does not authorize the Runtime to decide product meaning, approval, Brain review, user acceptance or merge.

canonical_rule_id: RULE_PHASE2D_DERIVED_RESUME_VIEW
source_section_id: 24::DERIVED_RESUME_VIEW

CURRENT_RESUME_VIEW is mechanically rendered from the current Task Capsule and, when available, its exact Handoff Projection and execution-review fiber. It is DERIVED_VIEW_ONLY, is not a persistent project fact or Session database, and cannot replace the bound current objects.

canonical_rule_id: RULE_PHASE2D_DELTA_REWORK_CONVERGENCE
source_section_id: 24::DELTA_REWORK_CONVERGENCE

A failed or interrupted execution attempt resumes from the still-valid mutation execution envelope plus the recorded remaining blockers, follow-ups and truthful residuals. Implementation defects inside the same envelope may use bounded rework under the existing mutation approval. Settled non-goals and approved semantics are reopened, and a new mutation approval is required, only when product meaning, accepted consequences, material scope, active invariants, minimum validation, source binding or another material envelope component changes.

canonical_rule_id: RULE_PHASE2D_SKILL_SYSTEM_REJECTED
source_section_id: 24::SKILL_SYSTEM_REJECTED

Phase 2 does not add a Skill registry or Skill-selection layer. Repeated deterministic mechanics remain explicit Runtime functions or repository tools. This avoids selection ambiguity, hidden semantic preconditions, version drift and extra model context.

canonical_rule_id: RULE_PHASE2D_EXACT_RESUME_SOURCE_BINDING
source_section_id: 24::EXACT_RESUME_SOURCE_BINDING

When CURRENT_RESUME_VIEW consumes a Handoff Projection, the Projection must pass schema and digest validation, bind the same project/task/round/Capsule, and, after execution approval, match the exact approved Projection binding. A same-Capsule fake or stale Projection cannot seed recovery.

canonical_rule_id: RULE_PHASE2D_FAILURE_DELTA_REQUIRED
source_section_id: 24::FAILURE_DELTA_REQUIRED

A Codex block, Brain Review block, or user acceptance block must leave an evidence-bound current-round rework delta stating the affected subject, remaining gap, next allowed action and bounded reopen scope. Resume renders this delta; it may not claim an empty remaining state after a blocking outcome.

canonical_rule_id: RULE_PHASE2D_TARGETED_STRUCTURAL_REWORK_AND_REGROUND
source_section_id: 24::TARGETED_STRUCTURAL_REWORK_AND_REGROUND

A Brain structural `REWORK` reopens only the exact unresolved structural subject and targeted discovery scope; it does not restart whole-project architecture discovery. If a Structural Repair merge changes the repository basis, the original product goal may continue but its prior structural projection, final path and execution approval are stale and must be re-grounded against the new repository before mutation resumes.
