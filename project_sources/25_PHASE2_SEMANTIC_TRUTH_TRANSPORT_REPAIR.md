# Phase 2 Repair — Semantic Truth Transport Across Existing Phase 1 Objects

canonical_rule_id: RULE_PHASE2_SEMANTIC_TRUTH_TRANSPORT
source_section_id: 25::SEMANTIC_TRUTH_TRANSPORT

Phase 2 extends existing Phase 1 objects but does not weaken Phase 1 truth boundaries. Every material Phase 2 claim that can affect execution, review, acceptance or recovery must carry the correct authority basis, compatible evidence, and exact current object/scope binding before it can be consumed as confirmed input.

canonical_rule_id: RULE_PHASE2_RECORDED_BY_DOES_NOT_CREATE_AUTHORITY
source_section_id: 25::RECORDED_BY_DOES_NOT_CREATE_AUTHORITY

Who structures a record is separate from who owns the underlying decision or fact. The Web Brain may record a user decision, Codex result or repository observation in structured form, but the record must bind the corresponding USER_DECISION, EXECUTION_EVIDENCE or REPOSITORY_EVIDENCE. No role gains authority merely by writing the field.

canonical_rule_id: RULE_PHASE2_EVIDENCE_COMPATIBILITY
source_section_id: 25::EVIDENCE_COMPATIBILITY

A reference that merely exists is insufficient. The evidence authority, kind, subject and current-object relation must be compatible with the claim it supports. Product-decision evidence cannot substitute for current-source inspection; Brain inference cannot substitute for user risk acceptance; stale or unrelated evidence cannot satisfy a current review conclusion.

canonical_rule_id: RULE_PHASE2_NO_NEW_TRUTH_LAYER
source_section_id: 25::NO_NEW_TRUTH_LAYER

This repair adds no Skill system, persistent Resume database, capability knowledge graph, automatic promotion or new authority. It strengthens the transport of Phase 2 semantics through the already-existing Task Capsule, Handoff Projection, Evidence Registry, Brain Review and User Acceptance chain; a Merged Change Projection is only a conditional post-merge navigation derivative, not a mandatory truth or Gate layer.

canonical_rule_id: RULE_PHASE2_LAYERED_PACKAGE_IDENTITY
source_section_id: 25::LAYERED_PACKAGE_IDENTITY

A cumulative Phase 2 candidate keeps the exact Phase 1 model, bootloader, stage lineage and inherited rules as its validated foundation while the current candidate identity is taken from the exact current `PACKAGE_MANIFEST.json` and `PHASE2_STAGE_LINEAGE.json`. The full-package validator must validate both layers without forcing the current Phase 2 README, repair matrix or candidate status to impersonate the Phase 1 candidate. This is one repository/package fact chain, not a second truth source.

canonical_rule_id: RULE_PHASE2_CLAIM_SUPPORT_RELEVANCE
source_section_id: 25::CLAIM_SUPPORT_RELEVANCE

Correct authority and evidence kind are necessary but not sufficient for a material Phase 2 claim. The supporting decision, discovery, validation or review evidence must be explicitly bound to the exact current claim subject it supports. Task-local subject binding reuses the existing Evidence Registry: operating assumptions bind to `OPERATING_ASSUMPTION`, prior behavior source/review binds to `PRIOR_BEHAVIOR`, authorized evolution binds to `PRIOR_BEHAVIOR_DISPOSITION`, impact coverage binds to `IMPACT_DIMENSION`, critical-risk control binds to `RISK`, and closed exit conditions bind to `EXIT_CONDITION`. This is a task-local relevance relation, not a persistent claim database or knowledge graph.

canonical_rule_id: RULE_PHASE2_SINGLE_USER_RELEVANCE_BOUNDARY
source_section_id: 25::SINGLE_USER_RELEVANCE_BOUNDARY

Joyflow is a single-user development workflow. This repair does not add user identity, authentication, signatures, multi-user approval, or cross-user authorization. The relevant failure is semantic reuse: one decision by the same user about subject A cannot silently authorize or confirm unrelated subject B.

canonical_rule_id: RULE_STRUCTURAL_COGNITION_EXACT_LINEAGE_TRANSPORT
source_section_id: 25::STRUCTURAL_COGNITION_EXACT_LINEAGE_TRANSPORT

Material structural truth is transported through existing Phase 2 objects by exact current-object identity, not by repeated prose. The Brain structural frame binds the requested question/dimensions; the Codex structural Return binds that frame and current repository observations; the Brain architecture disposition binds one exact Codex route; Final Path and the mutating Handoff bind the accepted structural closure; the Codex execution result binds the approved closure and reports actual structural consequences; Brain Review binds and dispositions the exact consequence set. No stage may recreate an equivalent-looking structural object with a new meaning while claiming continuity.

canonical_rule_id: RULE_EVIDENCE_TRANSPORT_EXACT_LINEAGE
source_section_id: 25::EVIDENCE_TRANSPORT_EXACT_LINEAGE

Evidence transport adds no new semantic truth layer. The Codex Return binds the exact current-round Evidence Bundle digest; an optional GitHub receipt binds only the transport object carrying that same bundle. Brain re-fetches and hashes the exact GitHub object, then validates the contained current-round evidence identity before semantic review. Evidence capture mechanism, Evidence Bundle, transport mechanism, transport integrity, Brain judgment, product PR result and long-term repository fact remain orthogonal and may not be collapsed into one PASS/FAIL state.



canonical_rule_id: RULE_EVIDENCE_TRANSPORT_CLEANUP_EXACT_LINEAGE
source_section_id: 25::EVIDENCE_TRANSPORT_CLEANUP_EXACT_LINEAGE

Ephemeral Evidence cleanup preserves exact lineage from the original user-approved mutating Projection to the current-round transport receipt and then to current terminal review evidence. The cleanup continuation may not be reconstructed from a branch name alone, may not reuse a receipt from another task/round, and may not delete a ref that has moved away from the receipt's exact transport commit. Cleanup lineage proves only authority and target identity for the bounded deletion; it does not create a new review, acceptance, merge or project-truth state.
