## Placement

`User/Web Brain -> Frozen Design -> Projection/Contract -> optional bounded Class-AI helper -> effective contract -> cold read/mechanical gates -> Codex -> Machine -> Evidence/currentness -> Brain/User review -> user merge boundary`

Class-AI does not create Product meaning, Authority, implementation authorization, native currentness, acceptance, merge authorization or a second contract truth.

## Strong DIRECT

Joyflow already uses deterministic mechanics such as schema checks, digest/current-object binding, path validation, Machine validation, receipts/currentness and fail-closed gates. Class-AI may help produce candidate successor deterministic mechanics, but any durable implementation change remains subject to the existing design, verification, authorization and repository lifecycle.

## P0 boundary

Class-AI does not replace mechanical handling of crash/re-entry, currentness, effect eligibility, package/current-object drift, terminal receipts or PR lifecycle. UNKNOWN remains UNKNOWN where native evidence is insufficient.

## Required implementation replay

- ALREADY_EXPRESSIBLE

Prefer existing expression or composition. Add a narrow carrier only for a demonstrated gap. No global Class-AI manager or new semantic control plane is required by current evidence.
