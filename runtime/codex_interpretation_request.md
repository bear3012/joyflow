# Joyflow Codex Execution Interpretation Request

This is read-only semantic handshake work. Do not modify repository files, create commits, push, open a PR, or write approval evidence.

Lifecycle mode: `REFERENCE_CANDIDATE`

A `REFERENCE_CANDIDATE` is not an active task. Use this template only after a real task changes lifecycle mode to `ACTIVE_TASK`.

## Original problem

Repair and optimize Joyflow so the human and Web Brain close product meaning, Brain compiles a dual-layer contract, local Codex returns understanding and bounded implementation evidence, Brain reviews semantic drift, and the user validates the real experience before final acceptance.

## Objective

Make Joyflow's three-layer anti-deviation design mechanically honest and ready for a second unfamiliar cold review before any real human acceptance run.

## Expected user-visible result

The package can be safely inspected and installed, but it cannot execute until a real active task supplies authentic reviewed Codex understanding; later evidence cannot silently drift from current source or user meaning.

## User flow

- User and Brain close product meaning.
- Brain creates the dual-layer contract and fixed acceptance cases.
- Reference candidate remains blocked during package review.
- A later real ACTIVE_TASK obtains authentic Codex interpretation and Brain alignment.
- Codex executes one complete Prompt within allowed writes.
- Brain and user separately review the same current evidence bindings.

## Must preserve

- Web Brain semantic authority.
- Local Codex bounded execution.
- Human transfer and final acceptance.
- GitHub durable baseline.
- Bridge as only mutation carrier.
- Validator as non-semantic mechanical layer.
- Existing four-file subject core shape.

## Allowed solution surfaces

- AGENTS.md and .codex rules.
- Routing, path, diff, hash, Bridge, Prompt, check, and Reconcile scripts.
- Semantic closure specifications and runtime reference artifacts.
- Mechanical tests and GitHub Actions workflow.
- Observer candidate evidence state.

## Forbidden consequences

- No active execution from reference mode.
- No fixture interpreted as execution evidence.
- No Codex write access to Brain or human approvals.
- No stale generated runtime accepted by CI.
- No substring risk false positives.
- No hidden-path identity loss.
- No clean-worktree substitute for PR diff.
- No HARD_STOP closure.
