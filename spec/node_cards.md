# Node Cards

## H3_PRODUCT_WALKTHROUGH

Brain reverse-restates entry, user actions, system responses, success, failure, preserved behavior, and explicitly absent behavior. The human confirms actual use, not implementation design.

## H4_PRODUCT_MEANING_CLOSURE

Brain records confirmed product meaning. No material ambiguity may remain before an ACTIVE_TASK.

## H5_DUAL_LAYER_TRANSLATION_CONTRACT

Brain records the human semantic layer, mechanical execution layer, lifecycle mode, Golden Case references, Meaning Delta, acceptance plan, allowed paths, and stop conditions.

## N1_ROUTE_TASK

Routing examines intended execution surfaces only. Non-goals and negative examples do not create risk hits. Matching uses complete token/phrase boundaries, so `product` does not match `prod` and `authority` does not match `auth`.

`REFERENCE_CANDIDATE` always routes to HARD_STOP.

## N3_BUILD_BRIDGE

Bridge is the only mutation carrier. It binds source and authority input hashes and separates executor, Brain, human, and later machine outputs.

## N5B_CODEX_EXECUTION_INTERPRETATION

A fixture is not execution evidence. ACTIVE_TASK requires a real `CODEX_EXECUTION_RETURN` reviewed by Brain.

## N8_RUN_CHECKS

Checks compare base-to-head committed changes, validate full input hashes, preserve hidden paths, and reject stale generated artifacts in CI.

## N9A_BRAIN_SEMANTIC_REVIEW

Brain review binds current HEAD, Bridge, input bundle, and source bundle. It cannot rely on an earlier source head after material changes.

## N10_USER_ACCEPTANCE

Human-origin acceptance binds the same current facts and covers every predefined acceptance ID.

## N11_RECONCILE

HARD_STOP, non-released execution, HALT packet, reference mode, stale evidence, incomplete Brain review, incomplete PR evidence, or incomplete human acceptance always block closure.
